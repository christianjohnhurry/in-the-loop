# Repo layout

Where things live and what each file does. For what the TUI looks like on screen, see [`ui.md`](ui.md).

```
in-the-loop/
├── README.md                      Install, run, and a page-by-page guide
├── CHANGELOG.md                   One entry per ticket; version bumps in package.json
├── package.json                   review-tui package, scripts (start, test, lint, eval:judge)
├── bun.lock                       Locked dependencies
├── tsconfig.json                  TypeScript settings
├── eslint.config.js               Lint rules (Google-style TypeScript)
├── .prettierrc                    Formatting rules
├── .gitignore                     Ignores node_modules, build output and reviews/
│
├── src/                           The review-tui app (Bun + OpenTUI)
│   ├── cli.ts                     Entry point: parse args, open the review, start the TUI
│   ├── target.ts                  Pick the PR: the URL argument, else the open PR for this branch
│   ├── tui.ts                     The terminal UI: pages, key handling, drawing, glue to everything below
│   ├── start.ts                   Start page: logo, repo/branch/model lines, model picker
│   ├── pager.ts                   Page body: one scroll region per page under the fixed tab bar
│   ├── theme.ts                   The one colour palette and styled-text helpers
│   ├── logo-svg.ts                Renders the start-page logo as SVG (for the README)
│   ├── types.ts                   Shared types: PR info, state, inline comments, verdicts
│   ├── store.ts                   Per-PR state on disk: state.json, comments.md, diff.patch
│   ├── github.ts                  gh calls: fetch PR and diff, parse the diff, validate comment
│   │                              lines, build and post the review payload
│   ├── checklist.ts               The eleven review steps and "is it complete?"
│   ├── gates.ts                   Rules for starting the review (checklist, intention, comments)
│   ├── llm.ts                     OpenCode client: ask an agent, judge intentions, review comments
│   ├── model.ts                   Model choice: parse provider/model, list, filter, pick default
│   ├── guard.ts                   Guardrail on the judge: only a clean pass/retry and a capped hint
│   ├── enquire.ts                 Enquire page's model call: caps input and output sizes
│   └── ide.ts                     VS Code client: find the extension, connect, track selection,
│                                  turn it into a comment target
│
├── test/                          bun test unit tests, one file per area
│   ├── core.test.ts               Checklist, gates, guard, diff and payload
│   ├── enquire.test.ts            Enquire input and output limits
│   ├── ide.test.ts                IDE discovery, connection and targets
│   ├── model.test.ts              Model parsing, filtering and defaults
│   ├── start.test.ts              Start page and logo (fails if docs/logo.svg is stale)
│   ├── target.test.ts             PR selection from URL or branch
│   └── fixtures/sample.diff       Small diff used by tests and the judge eval
│
├── scripts/
│   ├── eval-judge.ts              `bun run eval:judge`: five canned cases against a live model
│   └── logo.ts                    `bun scripts/logo.ts`: regenerate docs/logo.svg
│
├── .opencode/agents/              Read-only agents the LLM calls run as
│   ├── review-judge.md            Intention judge and comment feedback
│   └── review-enquire.md          Enquire page: explains code, never reviews it
│
├── vscode-extension/              VS Code extension that shares file and selection
│   ├── README.md                  Build and install
│   ├── package.json               Extension manifest
│   ├── src/extension.ts           Entry point: watches the editor, feeds the server
│   ├── src/server.ts              Local WebSocket server, token-authenticated
│   ├── src/lock.ts                Writes and removes the lock file clients use to find it
│   ├── src/lines.ts               VS Code ranges to 1-based line ranges
│   ├── src/protocol.ts            Message and lock file types
│   └── test/server.test.ts        Server tests
│
├── docs/
│   ├── ui.md                      What the TUI looks like, its keys, and how data flows
│   ├── repo-layout.md             This file
│   ├── ide-protocol.md            The VS Code to review-tui message protocol
│   ├── design/enquire-page.md     Design and guardrail rules for the Enquire page
│   └── logo.svg                   README logo, generated by scripts/logo.ts
│
├── .github/pull_request_template.md   PR template
│
└── reviews/<repo>-<pr>/           Created at run time, git-ignored
    ├── comments.md                The reviewer's intention and comments
    ├── state.json                 Checklist, intention, page, feedback, model
    ├── diff.patch                 The PR diff
    ├── review-body.md             The edited review body, after `b`
    ├── payload.json               The review payload, after `p`
    └── errors.log                 LLM failures, if any
```
